# 按能力接入不同 AI 平台

共用同一内容契约、固定模板、`run` 控制器与独立美术契约。平台适配只负责输入文件、执行工具、图像返回与预览入口，不另写一套页面或改变人物分析。ChatGPT 网页、Claude 网页、Codex、Cursor 及其他宿主均先检查本次真实能力；平台名称、模型自述或能读取 GitHub URL 不等于有完整执行环境。

## 最小能力与路线

| 当前能力 | 本项目实际可走的路线 | 交付边界 |
| --- | --- | --- |
| 文件读写、Python 3.10+ 与依赖 | 上传完整资源包或 bootstrap 获取同一 revision，调用 `run` | 可以构建固定模板 HTML；浏览器、生图仍分别检查 |
| 上述能力及实际生图、参考图和原生透明输出 | 独立卡片模块生成原型与层，`run --layers` 自动续跑接入 | 可完成分层卡文件，视觉与互动仍须实际验收 |
| 可执行但缺生图或原生透明输出 | 先交付已验收 HTML，保留已有静态预览与卡片待办 | 专属原生 SSR 尚未完成，不能代码画图凑齐 |
| 文件可上传下载但无代码执行 | 当前无法自动执行 Python 构建器 | 不声称已生成个人 HTML；手动查看器仅在用户选择后使用 |
| 只能聊天文本 | 可协助整理有依据的内容，无法执行完整产物链 | JSON 或文字不算已经请求的 HTML 和分层卡 |

本项目未附带部署好的网页构建服务、MCP 服务或自动接入网关。完整 ZIP 是资源与执行说明，上传不会自动安装这些工具，也不能强制宿主在生图后继续执行。若宿主的图像模式返回图片就结束、不能取回文件续跑，应选当前已可用的可持续执行工具/内部子任务；没有这种能力时明确整条路线未满足，不反复让用户发“继续”。不要为一次生成新建无关账号、自动付费 API 或公开上传个人资料。

## 宿主执行者自行检查

1. **资源与文件**：能否解包/下载完整项目、读取同版文档、保存并返回真实工件；用 bootstrap 检查目录与模板锁。资源缺失时不自由重写页面。
2. **执行**：实际 Python 版本、`requirements.txt` 依赖和允许输出目录；需要修复时由 AI 在当前授权环境处理并重查。
3. **图像**：当前会话确有可调用工具，能使用同一原型参考、返回合法 3:4 全画布及原生透明 PNG。能生成图片但不能透明输出时，只能保留静态原型预览。
4. **排字**：生成前确认可用中文字体；`run` 对待生成卡片预检字体可加载，支持 `--font <真实字体文件>`，已完成文字层无需重新排字。`prepare_card_layers.py` 同样支持自动查找或 `--font`。字体可加载不证明每个中文字形覆盖，最终仍逐字看成品；缺字体时由 AI 修排字环境，不让图像模型画 SSR、中文或署名。
5. **运行预览**：本地浏览器与聊天内预览分别检查。浏览器是否允许完整 JavaScript、WebGL、音频与本地附件；有实际 Chrome/Chromium 时传 `--browser`。没有时保留文件核验、使用 `--no-browser`，明确动态未验证。聊天内预览按下一节选择实际入口，不用模型名称推定可用。

不向用户发工具问卷。上述检查属于 AI 的内部执行责任；无法自行解决的具体缺口用一句话报告，已完成结果仍保留。

## 把真实 HTML 接入聊天内预览

用户明确要求“在 GPT/聊天里直接渲染、可操作、不要下载再看”时，首次 public `run` 使用 `--require-in-chat-preview`。这是持续的交付条件；后续不能因为文件构建成功就移除。默认也优先展示真实预览，但未提出站内交互要求的文件交付无需增加这一硬条件。

按当前会话可用工具的实际说明选择路线，不能只在回复里写“已放入 Canvas”或伪造工具调用：

| 实际入口 | 执行动作 | 能确认什么 |
| --- | --- | --- |
| 原生 HTML / Canvas / Artifact 可执行预览 | 从构建文件直接读取并交给该入口，按其真实参数和输出引用展示；在聊天内操作 V10 | 最终相同文件与关键交互通过后，才能记录聊天内可用 |
| 仅支持小型 HTML 片段的可视化工具 | 先核对大小、文档结构、资源和脚本限制；只有能保持同一成品时才尝试 | 不能把多 MB 的完整文档当片段硬塞，也不能删图、音频或重写简版后算原 V10 通过 |
| 桌面应用内置浏览器 / 本地浏览器 | 打开原文件；仅接受 HTTP 时使用下面的本地预览方式 | 验证实际作品，可作为看图与动态证据；不自动证明聊天内原生预览可用 |
| 只能下载附件 | 返回真实文件与实拍预览，保留聊天内要求未满足 | 文件可取回；下载按钮、文件图标或静态截图都不等于可交互 |

优先在基础星系构建后确认入口是否接受当前模板，再在最终内嵌卡片后复查同一入口。通过后按 `delivery-v2.md` 记录最终文件哈希和实际交互；若预览工具重写文件，不能沿用原文件的通过记录。工具若只能在最终回复中首次显示、宿主无法在本轮观察，状态保持 `not_tested`，不能提前自证通过。

若入口拒绝大小、脚本、WebGL 或资源，记录实际错误并保留成品；不能把去掉效果的降级品计作原请求完成。现有下载 HTML 仍能在现代浏览器直接打开，无需安装 Node.js、Python 或服务器。仅接受 HTTP 的本地浏览器工具可以使用只服务待预览文件、绑定 `127.0.0.1` 的临时服务；这不是让云端聊天访问本机的发布地址，不服务私人历史目录，也不自动部署。

仓库现有浏览器查看器是手动导入兼容路线，尚不是自动分析、生图、组装服务。用户明确选择它时才使用，并保留真实生成与验收边界，不算默认一次请求路线已完成。

## 平台验收

分别记录宿主、实际模型/工具、资源获取方式、原始资料、完整一次请求和实际工件。按 [fresh-generation-eval.md](fresh-generation-eval.md) 验证当前接入，区分文件完成、动态通过、卡片质量与整体完成。某一本机试验或平台通过不代表其他平台认证；失败、缺工具和未测试均保留，不以品牌列表替代实测。
