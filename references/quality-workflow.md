# 美术生产工作流：先选好画，再做闪卡

本页是默认美术入口。程序管理证据和状态，宿主负责真实生图与实际看图。详细字段按需读 [art-evidence-format.md](art-evidence-format.md)，命令见 [../CARD.md](../CARD.md)；完整审美/分层原则见 [art-direction.md](art-direction.md)。不要把这些文档整体转发给图像模型。

## 1. 在生成前解决三个问题

**偏好。** 继承当前用户明确喜欢、明确否决的视觉方向与可见参考，不重问已知信息。不把旧坏图换标题再次交付；有可用旧文件时记录其 sha256 到 `preferences.rejected_asset_sha256`。这份记录只在当前私人工作目录，不写进公共仓库或所有人的默认风格。

**能力。** 确认本次实际工具支持绘画、引用同一原型和真正透明输出；确认中文字体可读取。能写 PNG 或 Python 并不等于能绘画。缺能力就保留成功模块并说明缺口；不画几何占位冒充，不付费接入未经授权服务。不要为了追求固定名义尺寸重采样；采用实际工具支持且返回的合法 3:4 全画布。

**画面。** 内部比较两三个方向，选一个主导视觉语言。把行为/气质转换成一个具体主体、一个动作或结构、材质、光线和有意留白，而不是把职业关键词逐一变成标志。物件与人物均可，但必须已经被设计清楚。参考只借视觉语言，不借他人身份与经历。无实际可见参考就 `reference_basis=text_only`，不谎称看过图。

将上述决策写为独立 `art-direction-1` JSON，使用当前 persona_digest。`scene` 的八项必须具体；主题排字颜色、边框与遮罩服从画面，不强制蓝金色/双边框。程序把 `scene` 与 `keep/avoid` 编译给图像模型，执行规则、来源账本和设计比较不会混入视觉 prompt。

## 2. 无字原型关口

真实调用图像工具生成 `prototype.png`：无字、无框、无预烘焙镭射。保留完整工具返回、实际 per-call prompt、返回工件标识与原始字节。调用记录属于来源材料，不是填写“generated”就算发生过调用。

打开原型，先在缩略卡尺寸判断主体和焦点，再在原图检查形态/材质与细节。至少确认主体清楚、构图、材质、光线、偏好符合、辨识度和文字空间。移去称号和光效，画面本身还必须成立。只有实际通过才继续；不是把所有候选都生完、也不让用户承担选择工作。方向性失败时重做原型，别把坏原型锁死后投入更多图层工作。

可以用 `scripts/art_quality.py review-template ... --stage prototype` 计算当前 targets，生成的是 **pending** 模板。随后真实观察，留下具名意见与检查记录，再将文件 hash 登记到 `art-evidence.json`。`check --stage prototype` 通过后才执行独立层调用；该检查可在后续图层尚不存在时运行。

## 3. 原生分层与无字合成关口

每层引用选定原型，沿用实际全画布、朝向、姿态、尺寸、位置和光线。background 是完整不透明环境，不能包含第二主体；subject 包含主要主体/手持物；effects 仅少量前景；spirit 只有确有同伴时非空。

禁止抠图、纯色幕布转 alpha、裁切、缩放、重摆或把整张原型重复贴到几层。若工具多次配准失败，修失败层，不降低为工程示意图凑合。最多两次额外重试，必要时一次明确构图修订，保存旧参考和失败原因。

程序独立生成文字和由最终 subject alpha 派生的白底暗线 lineart；不得重画线稿主体。有内容的 spirit 必须显式传 `--spirit` 保留。新排字主题记录颜色、边框、遮罩与 footer_top，长文案换行/缩小到合理范围，仍放不下就拒绝而不是裁掉。

生成不含文字的 `composite.png`，与原型并排看：主体没有变形/走样，背景没有重复人像或影子，手持物只归一层，透明边缘没有残片，光线和材料一致。它不是第二张“重新画出来的合成”，必须是这些原生层的真实叠加。审查后登记 `composite` review，未过就回失败层，不加光效掩盖。

## 4. 最终卡面与互动关口

独立生成 `front.png` 和 `preview.html`。先看静态卡，再查看左右约 ±25°、关闭 foil 的层内位移、depth=0 的对照、恢复 foil 后视角驱动的光泽；确认文字固定、拖动不误翻、触摸/键盘与减少动态可用。手机检查实际标题、正文和按钮可读可达，不以没有横向滚动替代文字检查。

记录 `typography`、`visual_hierarchy`、`preference_fit`、`parallax`、`foil`、`mobile_readability` 的实际观察，保留左右和手机截图、检查记录；截图不能独自证明连续动作。调用/浏览器检查与观察分别记录。没有浏览器就不伪造动态检查。

最终 review targets 必须绑定实际 front 和独立 preview。第一次 public `run --layers` 会先产生候选文件；对这份实际文件评审并续跑。不同预览内容、任何图层或文案变化都要重新核验，不能只改哈希继承旧意见。

## 5. 一次请求内自动接入与交付

`art-evidence.json` 与最终 `layers.json` 相邻；本页所有相对文件引用均以该目录为根。工具返回图片可按原字节复制进去，不改变像素。工具原始输出记录去除凭证/敏感字段时应说明脱敏，不伪造返回内容。

回到相同 public `run`、输入、workspace 和 mode 续跑。完整卡需要现有机械检查 + 当前来源记录 + 三阶段真实评审；之后才接入固定 HTML。最终浏览器检查通过且 `complete=true` 才称此次所请求作品完成。`candidate_outputs` 可明确作为未完成预览展示，不能称原生闪卡验收通过。

`needs_art_evidence` / `needs_art_review` 是内部待办；不让用户再发“继续”。能力缺失或达到重试上限时交付实际成功部分与准确缺口。卡片失败不破坏基础 HTML，HTML 失败也不销毁卡片。禁止改模板锁、另写页面或用低层诊断命令绕过 public 交付关口。

## 这些记录不能证明什么

本地哈希和具名观察可以防止意外复用、漏步、素材改变后继承旧评审；不能认证外部服务，也不能阻止有写权限者主动伪造全部材料。程序保持 `quality_verified=false`、`generation_provenance_verified=false`。`art_reviewed_by_host` 是实际宿主观察，不是用户批准、审美客观评分或自动公开授权。

合成测试只证明关口行为，不能算真实生图成功率。稳定性评估应分别记录原型、无字合成、最终卡与浏览器的首次失败位置，用多个新资料重复真实运行；保留失败与工具阻塞，不能只展示最漂亮的一次。具体协议见 [fresh-generation-eval.md](fresh-generation-eval.md)。
