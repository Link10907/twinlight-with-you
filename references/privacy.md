# 隐私、确认与发布

默认本地处理；不得从未授权账户获取记录。宿主可能把输入交给其模型处理，这由宿主服务决定；“本地 CLI 无网络”不等于“整个 AI 工作流完全离线”。调用图像工具之前，只传获得许可的最小视觉 brief，不附原始聊天或第三方私人信息。

真实历史、原文证据、照片、分析、审查稿、批准收据放在 `private/`，或工作树外。公开源代码只含模板、程序素材和虚构 fixtures。`.gitignore` 只是误操作防护，不是加密或保证，提交前检查 `git diff --cached`。

`compile` 剔除原始引文与原生消息 ID。公开摘要仍可能间接识别个人。程序仅启发式检查常见密钥/邮箱/手机，不保证完全匿名化。敏感项不出现在公开事实闭包，想保留时先重新写脱敏的非敏感事实并重新核对。

本人需要核对：材料范围；本人/他人归属；计划/成果；旧信息更新；公开文案；人物形象；分享范围。AI 不能为了让构建成功自行替人执行 approve。

`approve` 记录分析哈希以及最终图层清单和文件内容哈希。变更任一部分后必须重新审查。该收据是本地审计记录，不是身份认证、版权凭证或法律授权书。

`share_allowed=false` 会禁用应用内的导出路径；用户仍可以截图、修改 HTML 或自行分享。所以必须在分享文件之前审查，不能把按钮状态当作防泄漏措施。

网页导入新 profile 会取消旧图像/旧评价绑定。私有卡需要重新生图再 build。不要把另一个人的 SSR 图或解释保留下来凑完整。

GitHub 推送是另一个明确动作。即使用户同意生成页面，也不能推送其私人资料；即使用户同意推送 Skill，也不等于同意推送他们的聊天。在连接报告权限拒绝时停止远程写入，不换私钥/令牌绕过。
