# 材料、确认与发布

两种模式只用本次授权资料与可见对话，不从未授权账户取得历史。记忆只能形成有限印象，不代表可核对 transcript 或全量账户覆盖。宿主可能把输入交给模型服务；本地 CLI 无网络不等于整个 AI 流程离线。

个人事实、称号、视觉符号和图像不得来自作者、`examples/` 或别的用户。每个 owner、workspace、analysis、layout、图层和确认记录分别保存；缺材料时说明缺口，不用示例补全。仅同一确认本人和获授权的既有工件可以增量复用。

真实历史、原文引用、照片、分析、审查稿和确认收据放在 `private/`、`runs/` 或工作树外；输出与运行报告默认不提交。检查 `git diff --cached` 的实际内容，`.gitignore` 只是误操作防护，不是加密。

默认分发包没有示例人物；演示包只含明确的虚构数据和虚构生成图层。源库的历史 `examples/showcase/` 含作者真实摘要与少量原话，保留用于溯源，排除通用 viewer 和两类分发包；不能因其存在、以前的发布或修改 skill 推定新的公开授权。维护者身份、上游署名和开发路径只是出处，不是个人判断的证据。

调用图像工具前只发送完成请求所需的最小视觉 brief，不附历史原文、第三方秘密或未授权照片。有照片才使用授权形象；否则是原创概念角色。原型与层按原生透明流程生成，不以抠图处理私人照片补成概念卡。

Lite 默认生成本地草稿无需先取得文案确认。`start --preview` 在校验内容后真实记录 review skipped（本人未确认），继续生图与构建，保持 `draft=true`、`share_allowed=false`；没有本人回复就不能写确认收据。草稿里的展示文字仍是未确认的有限印象，不能标成本人认定的事实或获准公开。

本人审阅时核对：材料范围、本人/他人归属、计划/成果、旧身份更新、全部展示文字、人物形象与分享范围。AI 不能代本人作出 `confirm` 或 `approve`，只能按真实授权记录；本人已明确同意确切当前文字时，可用其真实原话执行 `confirm --user-reply`，无需反复询问。后续真实确认可在同一 workspace 升级并重新构建；实质修改不能沿用旧确认。

Strict 保留来源审查、本人文字审阅与现有 `approve` 规则，不以 Lite 预览选项绕过。文案确认和本地草稿都不等于授权上传、部署或公开发布；不增加新的分享授权协议。

strict `compile` 会剔除源引文与原生消息 ID，公开摘要仍可能间接识别本人。隐私检查只是常见敏感格式启发式，不保证匿名化。需要脱敏时先修订事实与文本，再重新核对来源。

`approve` 绑定分析、图层清单与图片字节；修改需重新审查。这是本地确认记录，不是身份认证、版权凭证或法律许可书。像素检查也不等于本人批准图像。

`share_allowed=false` 禁用应用导出路径，但不能防截图、HTML修改或外部分享；按钮不是防泄漏机制。新 profile 导入会取消旧图像/人物评价绑定，不携带另一人的 SSR 卡。

分享 HTML 就会分享其中的摘要与图像。推送 GitHub、部署网站或对外发文件需明确指令；同意修改或推送通用 skill 不等于同意公开私人聊天与人物素材。确认原话和详细运行报告仅作为本人可选工件，不进入公共网页。
