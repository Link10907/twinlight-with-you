# 从原始资料开始的真实生成评估

本评估补上单元测试与已有素材转发没有覆盖的环节：宿主模型能否从陌生资料独立写出内容、调用真实图像工具、生成可用原生图层，并在一次请求中交付两个成品。本文是评估协议与覆盖边界，不是跨平台稳定性认证。

既有单元测试和浏览器检查只支持各自覆盖的程序行为；已有素材接入通过不证明新资料生卡成功。失败分享能读取对话文字，但未取得可下载的生成工件；可以核对模型说了什么，不能据此确认工件字节、模板、图层或渲染故障。缺工具、漏读 URL 所引用文件、模型偏离契约、图像工具能力不足需要实际证据区分。

2026-10-04 的本机审查完成了三个陌生虚构资料的独立 HTML-only 试跑，均通过当时版本的固定模板验收并保持私人草稿；逐份内容核对未发现他人归属、问题/掌握、计划/成果或助手虚构混用。首份另做了浏览器、连续播放及返回检查。这些是当时三个本机 HTML 案例的有限证据，不覆盖真实原生生图、完整双模块生成、URL 获取或其他网页/agent 宿主。当前控制器与模板锁修改后应单独回归，不继承旧试跑为新实现成功。

1.5.0 完善过程中另做了一次从虚构步行日记开始的独立 HTML-only 试跑：新内容通过来源人工核对，实际控制器、固定模板及浏览器检查通过，保留首次浏览器启动失败和成功重试。执行者读到了本文的历史汇总，故不称完全盲测。另以合成原生图层验证默认双模块续跑和接入，以最长合法中英文检查真实版面；这些回归不计为新生图成功，也不代表网页平台或实体手机认证。

## 输入与独立性

- 原始虚构资料位于 `tests/fixtures/fresh-generation/`。每份单独使用，不合并人物，不附预写 JSON、称号、主题、卡片答案或旧素材。
- 每次试验使用新聊天、新 run ID、新 owner 和空输出目录；禁读 `examples/`、作者经历及其他试验的个人内容/图像。固定模板、schema 和通用程序可复用。
- 至少跑三个资料案例；重复测量也重新生成，不复制上次结果。保留失败尝试与重试，不只保留最好的一次。每层最多重生成两次，按既有契约处理一次构图修订；失败后的静态预览不计完整卡成功。
- URL 路线和已安装完整 skill 路线分别记录。URL 路线需保存实际读到的入口、相对文档、脚本、模板版本与获取失败；看到首页文字不等于取得完整执行资源。
- HTML-only、card-only、默认 both 分别记录；前三份 HTML-only 不能计入完整 both 成功率。不同平台按 `platform-adapters.md` 记录能力，至少区分真实执行、生图/透明缺失、浏览器缺失与完整能力；不把工具阻塞从总样本删掉。

每次只发送一条请求，附一份原始资料及本次要测的入口：

> 根据附件中的这位虚构人物，按 Twinlight 流程生成定义闪卡和个人星系 HTML，完成后直接一起给我看。未指定的美术由你决定；这是尚未本人确认的私人草稿。

不以第二条“继续生图”“生成页面”“导入卡片”补齐成功标准。必要能力缺失时照实交付已成功部分，并记录本次整体未完成。

## 验收与证据

| 关口 | 必须保留的实际证据 | 可以确认的范围 |
| --- | --- | --- |
| 新内容 | 原始资料 hash、模型实际生成的只读输入、逐句来源核对 | 区分本人/他人、提问/掌握、计划/成果、旧说法/纠正；不以 schema 合格替代语义核对 |
| 图像工具 | 宿主实际调用记录、工具名、参考图、透明开关、返回文件与 hash | 确认确有生图调用；模型声称“已生成”和填写 manifest 不算调用证据，PNG alpha 也不能单独证明原生生成 |
| 原型 | 本次无字原型、读图记录、实际 3:4 尺寸与 hash、构图锁 | 后续参考同一原型；不能套旧坐标、裁剪拉伸或抠图装作新生成 |
| 原生层 | background/subject/effects 等原始输出、装层清单、校验结果 | 同画布、真实 alpha、不透明完整背景、人物绑定、图层字节与坐标；不等于审美合格 |
| 配准与视觉 | 正面及左右视角截图、alpha 边缘检查、具体读图意见 | 主体与原型一致、无重复主体/残影/露洞、形态与材质可信、焦点及文字清楚；需实际看图，程序只核对几何部分 |
| 互动 | 本次独立卡预览及最终页面的浏览器执行记录、帧/截图、环境 | foil 关闭时层内景深、depth=0 时消失、foil 恢复时随视角变化、文字固定；拖动、翻面、手机布局及页面揭卡/返回。截图存在不等于互动通过，CSS 回退不算 WebGL 通过 |
| 固定模板 | 构建调用、源模板版本/hash、当前输入与图层 hash、最终 HTML hash 的 template receipt | 收据与真实构建输出相符、资源内嵌、当前人物内容匹配。收据不是模型自行填写的品牌标签；receipt 缺失时模板来源仍待查 |
| 一次交付 | 同一请求的最终回复与可打开的 `front.png`、`preview.html`、`card-pack.json`（独立模块可为 `card.json`）、最终个人 HTML | 两个成品已自动接入并一起交付；“以后再生成”、通用查看器、原型或静态图都不能算完整分层卡交付 |
| 控制器 | 本次 `run-state.json`、`run-report.json`、只读 `content.json`、真实 `next_action` 与续跑调用 | 待办由 AI 自行完成，成功模块保留；缺层返回 `needs_card`，缺浏览器保留动态未验，不以命令结束替代完成 |

机械结果与视觉意见分开保存：`validate-art` 的合格不应被改写成“美术质量已自动验证”。检查保留 `quality_verified=false`；真实工具来源也不由 alpha 或机械打包自动证明。每次项目构建自动保存 template receipt 与实际渲染输入；用 `verify-site <site目录>` 先核对维护的模板锁，再从同一固定资源独立重建并逐字节比较。它可检出自写替代页面或未按维护锁修改的资源；不得先修改或重锁模板再宣称验收有效。锁和收据是本地来源核对，不是防伪签名，不证明绘画质量或动态交互。旧产物和浏览器 viewer 导出无此收据，不能称已受此项验证。

## 最小完成关口与记录

完整卡的完成关口至少绑定本次 persona、原型、全部层字节、装层清单、独立预览、正面和卡包的 hash；分别记录机械检查、实际互动检查与视觉观察。缺任一必要证据、文件改动或只写入 `passed` 时，完成状态应失效。视觉意见记录实际观察者、文件、视角和发现；它是有来源的判断，不是防伪签名，也不是自动证明美术质量。

每次记录：run ID / 原始资料与入口 / 宿主与模型（未知留空）/ 实际工具能力 / 尝试与重试次数 / 当前证据文件及 hash / 各关口的实测通过、实测失败、未测或工具阻塞 / 失败原文 / 最终实际交付 / 未验证项。失败和未测都保留在总样本中；只对实际执行的项目报告 `通过数/试验数`。三个案例即使全过也只说明这三次结果，不宣称 ChatGPT URL 路线稳定。

控制器回归还应覆盖：缺图层仍保留已验收 HTML、卡片失败不破坏基础页面、HTML 导入失败保留独立卡片、删除收据/篡改输出后不能继承通过、输入变化不能混入旧 workspace、有效图层更新能够续跑，以及 `--no-browser` 不伪造动态通过。另用合法长度极值文字检查桌面和手机真实版面，不能只检主题数量和页面滚动宽度。

准备宣称稳定时，可先对三个原始案例各独立重复五次，分别统计一次请求完整交付、事实错误、固定模板验收、原生层成功、视觉问题、重试次数与耗时，再在目标宿主重复。报告附实际 `通过数/总尝试数` 和能力范围；样本成功不意味着所有用户或任意平台保证成功。真实新生图、完整双模块、URL 路线和其他宿主仍按上述关口逐项补证。
